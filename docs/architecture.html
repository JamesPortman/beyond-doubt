Beyond Doubt — system architecture

One engine, seven games,
three languages, no guessing

The whole system is organised around a single claim: the player is never asked to guess. Everything else — how themes work, how the server verifies a score, how two people race the same board — follows from making that claim provable rather than promised.

1 · The idea underneath

A cell is legal to flip if and only if every world still consistent with the clues in play agrees on its value. Cells that agree are forced. Anything else is refused — not penalised, refused.

That one rule does an unreasonable amount of work. It makes the game fair, it makes racing meaningful (nobody can gamble ahead), it makes co-op play cooperative rather than lucky, and — as section 5 shows — it is also what lets a client play instantly while a server stays the authority.

How a board is represented

A whole board state is one 32-bit integer: bit i set means cell i is in the marked state. Every clue compiles to two or three bit operations, so "enumerate every consistent world" is a tight loop rather than a solver library.

// "In row 2, exactly two are guilty" compiles to:
popcount(world & ROW_2_MASK) === 2

// and the solver walks every world the player has not ruled out:
let sub = freeMask;
for (;;) {
  const world = knownB | sub;
  if (clues.every(c => c.test(world))) { alwaysB &= world; alwaysA &= ~world; }
  if (sub === 0) break;
  sub = (sub - 1) & freeMask;   // classic submask enumeration
}

limit This caps out at 21 free cells — 2·106 worlds, a few milliseconds. 4×4 and 4×5 boards are instant. A 5×5 board would need a real constraint propagator; the interface would not change.

2 · The layers

Dependencies point downward only. The engine has never heard of a theme, a language, or a player.

3 · Theme is a skin layer

Seven games ship. They share one generator, one solver and one clue grammar. A theme is a data file:

{
  id: 'orchard',
  artKind: 'tree',                 // which drawing function
  tagSchema: { variety: [...] },     // powers relational clues
  palette: { /* page chrome AND tile material — different surfaces */ },
  strings: { en: {...}, pt: {...}, es: {...} },
}

Register it and the generator, solver, hint system, scoring, editions, leaderboard, accessibility modes and all three languages work on it immediately. Nothing else is touched.

Artwork is drawn, not fetched

Each tile's picture is inline SVG generated from the board's label seed. Six drawing functions cover the seven themes. This buys determinism (same board, same faces, in every language, offline), state-awareness (a guilty guest is struck through, a blighted tree loses its fruit, a forged canvas cracks), and free theming. The game page — seven themes, three languages — builds to one self-contained ~260 KB HTML file.

One theme is the exception: Auction Night declares an images set — 21 paintings and photographs in demo/assets/gallery/, dealt from the label seed and marked with a red dot when sold, since a photograph cannot be redrawn. Those files load at runtime; the single-file build has no assets beside it and falls back to the drawn tile.

4 · Why the language layer is not string substitution

A clue is an AST, never a sentence:

{ k: 'count', sel: { k: 'row', r: 1 }, state: B, cmp: 'eq', n: 2 }
localerendered
enIn row 2, exactly two trees are blighted.
ptNa fileira 2, exatamente duas árvores estão doentes.
esEn la fila 2, exactamente dos árboles están enfermos.

"Tree" is feminine in Portuguese and masculine in Spanish, so the numeral, the article and the adjective all change. That gender belongs to the theme, not the engine — switch to The Guest List and the same clue renders exatamente dois convidados são culpados. Person names carry their own gender too, because Nadia é culpada and Owen é culpado are different words.

Consequence: themes declare gendered nouns and full four-slot predicate forms, and nothing anywhere concatenates an adjective onto an unknown noun. Adding a language is one file implementing Locale; adding a theme is one data file. Neither touches the other, and neither touches the engine.

5 · Server-verified play

Ranked scores need an account, and the design goal was that a determined player with devtools open gains nothing.

The trick that makes it feel instant

The client is never sent the answer — but it does not need to be. A forced cell has, by definition, the same value in every world consistent with the clues the client legitimately holds. So the client can derive the answer for legal moves and paint them with zero latency, while remaining unable to learn anything about cells that are not yet forced. The server re-checks every move regardless. Authority and responsiveness, without a round trip per tap.

Not solved, and not solvable this way: two people at one screen, or photographing a friend's board. That is a social problem, and every daily puzzle game has it.

6 · Multi-user

Split clues

One device. The clue set is dealt across 2–4 players and nobody can finish alone. Changes no rule: legality stays global, so the table collectively knows enough. The game becomes people talking. Shelved, not deleted: Session.cluesFor() and dealClues() are still in the engine and still tested, but the demo no longer offers the tab.

Rooms

Several devices. Everyone races the same edition on their own copy. A six-character code, readable aloud — no vowels, no 0/O/1/I.

Presence is honest by construction

A player's progress is computed from the moves the server already validated, not from anything their client reports. There is no "my progress" field on the wire, so there is nothing to falsify. Each heartbeat carries only the tile the player is currently looking at, and returns everyone's position.

POST /api/room/heartbeat  { roomId, focusCell }
→ players: [{ displayName, revealed, total, mistakes, focusCell, finished, idleSeconds, you }]

Polling every 2.5 seconds rather than a socket: it is enough for a race, it survives sleeping laptops and flaky wifi, and it needs no stateful connection — which matters if you deploy serverless. Players who stop beating go stale rather than vanishing.

7 · Editions, scoring, leaderboards

  • Daily — one board, difficulty 1–7 Monday to Sunday, streaks tracked. The day rolls over on Eastern time (America/Toronto), not UTC.
  • Weekly edition — seven boards in one skin, ranked as a set. Days ahead of today are locked.
  • Archive — every daily back to the launch date, ranked on that day's own board (first attempt only), but recorded as late so it cannot back-fill a streak or a finished week.
  • Free play — server-chosen seed, never ranked, and shareable as a link because a seed is the whole scenario.

Scoring weighs time against par for the difficulty, multiplies by difficulty, deducts a flat penalty per hint, and adds a minute to the clock per mistake — a clean Sunday outranks a fast Monday. Speed is capped so an implausible solve cannot run away with the board. Weekly standings rank by days completed first (distinct days, not results) and total score second: finishing all seven beats one enormous Tuesday.

8 · Accessibility as a derivation

Appearance (dark/light) and colour mode (normal / high contrast / colour-blind safe) are computed from each theme's palette, not hand-authored per theme. A new theme inherits every mode the moment it is registered. Only page chrome is recoloured; the tile keeps its material, because the artwork carries the theme.

A test walks 7 themes × 3 appearances × 3 colour modes and asserts WCAG contrast on body text, panel text, tile captions and secondary text. It caught two real failures the first time it ran: Cold Open's cork background put secondary text at 2.84:1, and "high contrast" left black ink on that same cork at 5.8:1 because it was only changing the ink. Both were fixed in the derivation, not in the test.

9 · Deployment

Static onlynonethe client already falls back to local play when no server answers

Two properties make serverless viable at all, and both were designed in rather than patched on: every cache is rebuildable (puzzles regenerate from their seed, play state replays from validated moves, and a cached play is trusted only while its move, mistake and hint counts match the database row), and rate limiting reads the database.

On Vercel, vercel.json builds the engine and the demo into demo/dist and rewrites every /api/* route to one function, api/index.ts, which runs the same GameServer as npm run serve over PostgresStore (src/net/store-pg.ts). It migrates on cold start, refuses to start without DATABASE_URL (or POSTGRES_URL), and delivers sign-in codes through Resend. npm run test:pg runs the whole server suite against Postgres, so both stores answer to the same tests. Operator feature flags (src/net/flags.ts) are enforced server-side and sit behind their own ADMIN_TOKEN; unset, /api/admin/* does not exist.

The deployment answers at its own domain root and under www.portman.ca/beyond-doubt/. src/base.ts recovers that prefix from location.pathname at runtime, and both the API client and the Auction Night artwork carry it, so one build serves both URLs.
